Domain model relations

Project ↔ Task ↔ Comment ownership plus optional User links.

Overview

Ownership chain (cascade delete):

  • Project → many Task → many Comment

Optional User links (ON DELETE SET NULL):

  • User owns many Project (owner_id)
  • User is assigned many Task (assignee_id)
  • User authors many Comment (author_id)

Entity-relationship diagram

Lifecycle rules

Action Effect
POST /users Creates a User
POST /projects with owner_id Creates Project linked to User (404 if missing)
POST /projects/{id}/tasks with assignee_id Creates Task; optional assignee
POST /tasks/{id}/comments with author_id Creates Comment; optional author
DELETE /projects/{id} Removes Project, Tasks, Comments
DELETE /tasks/{id} Removes Task and Comments
DELETE /users/{id} Removes User; owner_id / assignee_id / author_id become null

Status and priority enums

  • ProjectStatus — ACTIVE, COMPLETED, ARCHIVED
  • TaskStatus — TODO, IN_PROGRESS, DONE
  • TaskPriority — LOW, MEDIUM, HIGH
